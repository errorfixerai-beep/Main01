# Tube Pilot — Flutter App (Android + iOS)

Same backend as before (`tubepilot/backend` — nothing there changes except two small real fixes: mobile clients now get a `refreshToken` in the JSON response, and YouTube-connect can bounce back into the app via a deep link). This folder is only the **Flutter client**, replacing the HTML/JS frontend.

---

## 1. Install Flutter

https://docs.flutter.dev/get-started/install — pick Windows. After install, verify:
```bash
flutter doctor
```
Fix anything it flags (Android SDK, Android Studio, accepted licenses via `flutter doctor --android-licenses`).

---

## 2. Scaffold the native Android/iOS projects

This zip contains `pubspec.yaml` + `lib/` only — **not** the native `android/`/`ios/` folders, because those must be generated by your local Flutter SDK (they contain machine-specific Gradle/Xcode files that can't be hand-written reliably). Do this once:

```bash
flutter create --org com.tubepilot --project-name tubepilot_flutter .
```
Run this **inside the extracted `tubepilot_flutter` folder** (where `pubspec.yaml` already sits) — Flutter will generate `android/`, `ios/`, `web/` etc. around your existing `lib/` and `pubspec.yaml` without overwriting them (it asks before overwriting `pubspec.yaml`; choose **N** so yours is kept).

Then install packages:
```bash
flutter pub get
```

---

## 3. Configure `lib/config.dart`

```dart
static const String apiBaseUrl = 'http://10.0.2.2:5000/api';
static const String googleServerClientId = 'your_WEB_client_id.apps.googleusercontent.com';
```
- `10.0.2.2` is how the **Android emulator** reaches your laptop's `localhost:5000`. On a **real phone**, use your backend's real deployed URL (or your PC's LAN IP like `http://192.168.1.5:5000/api` if testing on the same WiFi).
- `googleServerClientId` = the **same Web Client ID** already in your backend `.env` as `GOOGLE_CLIENT_ID`. Google Sign-In on mobile still needs the Web Client ID (as `serverClientId`) so the backend can verify the token — it is NOT the separate Android/iOS client ID from step 4.

## 4. Google Sign-In on Android — extra one-time setup

Mobile Google Sign-In needs an **Android-type OAuth client** registered against your app's package name + SHA-1 fingerprint (in addition to the Web client you already made).

1. Get your debug SHA-1:
   ```bash
   cd android
   ./gradlew signingReport
   ```
   Copy the `SHA1` value under the `debug` variant.
2. Google Cloud Console → Credentials → **+ Create Credentials → OAuth Client ID**
   - Application type: **Android**
   - Package name: `com.tubepilot.tubepilot_flutter` (or whatever `--org`/`--project-name` you used — check `android/app/build.gradle` → `applicationId`)
   - SHA-1: paste from step 1
   - Create (no client secret needed for Android type — that's normal)
3. You do **not** put this Android client ID anywhere in code — Google matches it automatically by package name + SHA-1 whenever `google_sign_in` runs.
4. For a **release** build later, repeat with your release keystore's SHA-1 (different from debug).

## 5. Google Sign-In on iOS — extra one-time setup

1. Google Cloud Console → Credentials → **+ Create Credentials → OAuth Client ID** → type **iOS** → Bundle ID = whatever's in `ios/Runner.xcodeproj` (`com.tubepilot.tubepilotFlutter` by default)
2. Open `ios/Runner/Info.plist`, add (replace `YOUR_IOS_CLIENT_ID` and the reversed form Google gives you on the credential's details page):
   ```xml
   <key>CFBundleURLTypes</key>
   <array>
     <dict>
       <key>CFBundleURLSchemes</key>
       <array>
         <string>com.googleusercontent.apps.YOUR_IOS_CLIENT_ID_REVERSED</string>
       </array>
     </dict>
   </array>
   ```

## 6. Deep link setup (needed for "Connect YouTube Channel" to return to the app)

When a user taps "Connect Channel", the app opens Google's consent screen in the **external browser** (can't be done inside the app for OAuth). After they approve, the backend needs a way to hand control back to the app — it redirects to `tubepilot://oauth-success`. Register that scheme:

**Android** — open `android/app/src/main/AndroidManifest.xml`, inside the `<activity>` tag for `MainActivity` (alongside the existing intent-filter), add:
```xml
<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="tubepilot" android:host="oauth-success" />
</intent-filter>
```

**iOS** — in `ios/Runner/Info.plist`, add another `CFBundleURLTypes` entry (or a second dict in the array from step 5):
```xml
<key>CFBundleURLTypes</key>
<array>
  <dict>
    <key>CFBundleURLSchemes</key>
    <array><string>tubepilot</string></array>
  </dict>
</array>
```

## 7. Backend `.env` — what changes

**Nothing needs to be removed.** Keep every existing key from your current `backend/.env`. Since the Flutter app talks to the exact same API, it reuses all of it: `MONGO_URI`, `JWT_SECRET`/`JWT_REFRESH_SECRET`, `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`, `GOOGLE_DRIVE_*`, `CLOUDINARY_*`, `GROQ_API_KEY`, `ADMIN_EMAIL`/`ADMIN_PASSWORD`.

Only double-check these two, since mobile now uses them too:
- `FRONTEND_URL` — keep the old web origins in the list (for the website), the Flutter app doesn't need an entry here since it isn't a browser origin and isn't subject to CORS.
- `GOOGLE_REDIRECT_URI` — stays exactly the same single backend URL (`http://.../api/youtube/oauth/callback`) — both web and mobile go through this one callback; the backend now branches internally (`platform=mobile` vs default) to send each back to the right place.

Copy the **updated backend files** (`routes/auth.js`, `routes/youtube.js`) from this delivery over your existing backend, then restart it (`Ctrl+C` → `npm run dev`).

## 9. What's real vs. what needs your keys (same as before)
- Real email/password auth, real Google Sign-In (verified server-side, same as web)
- Real diamond wallet: 10/50/100/200 packages only, manual UPI + UTR + screenshot → admin approve/reject
- Real file upload (video + optional thumbnail) via `file_picker`/`image_picker` → multipart to your existing backend → Cloudinary1 → Cloudinary2 → Google Drive → YouTube
- Real Groq AI title/description/tags generation
- Admin panel (visible only if your account's `role` is `admin` in MongoDB)

You still need your own MongoDB/Google/Cloudinary/Groq credentials in `backend/.env` exactly as before — nothing about the Flutter client changes what the backend requires.
